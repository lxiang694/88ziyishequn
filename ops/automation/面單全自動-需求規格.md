> 這份文件是要交給 AI（ChatGPT / Claude）照著實作的規格書。

## 0. 一句話目標

我給一串訂單號，程式自己去 7-11 賣貨便把那幾筆的交貨便面單印成 PDF、
一個訂單一個檔、檔名就是訂單號，然後自己開啟桌面的「新比銳國際物流」
程式，走「蝦皮相關 → 蝦皮面單上傳 → 選取 → 識別 → 上傳」，全部做完。

中間**不需要我點任何一下**。

---

## 1. 這是什麼性質的程式

**不是網頁、不是瀏覽器擴充功能。** 最後一段要操作 Windows 桌面應用程式，
只有本機程式做得到。

- 執行環境：Windows 10/11 桌面
- 建議技術：**Python 3.11+**
  - 瀏覽器自動化：`playwright`（Chromium，**persistent context**，見 §3.1）
  - PDF 處理：`pypdf`
  - 桌面自動化：`uiautomation` 或 `pywinauto`（二選一，見 §5）
- 交付形式：一個資料夾，內含 `.py` 原始碼 + `requirements.txt` +
  `config.yaml` + `README.md`。我用 `python run.py` 或雙擊 `run.bat` 啟動。

---

## 2. 我怎麼下指令

最低要求：一個純文字檔 `orders.txt`，一行一個訂單號：

```
CM2609214719432
CM2609214719459
CM2609214719479
```

程式讀它、跑完、印出報告。

加分（不強制）：一個很小的視窗，我把訂單號貼進去按「開始」，下面即時
顯示每一筆的進度。

**訂單號格式**：`CM` + 13 位數字。面單上印的是 `CM2609214719432-0`，
結尾的 `-0` 是子單號，比對時要去掉。**多一位數字的（14 位）要整串拒絕，
不可以截前 13 位** —— 截出來會是一個合法但屬於別人的訂單號。

## 3. 階段 A：從賣貨便取得面單 PDF

### 3.1 登入怎麼處理

**不要寫帳號密碼自動登入**（會遇到驗證碼、簡訊 OTP，而且不安全）。

改用 Playwright 的 **persistent context**：

```python
ctx = p.chromium.launch_persistent_context(
    user_data_dir=r"C:\myship-bot\profile",
    headless=False,
)
```

第一次執行時程式偵測到未登入，就**暫停並提示我手動登入**，我登完按 Enter，
程式繼續。登入狀態會留在 `profile` 資料夾，之後不用再登。

Session 過期時同樣暫停等我，**絕對不要自己猜密碼或重試登入**。

### 3.2 操作步驟（照我手動的流程）

1. 進「賣家訂單」頁
2. 搜尋訂單號
3. 勾選該筆
4. 按「取交貨便代碼」
5. 按「列印交貨便代碼」
6. 會開出一個列印用的頁面（網址類似
   `https://epayment.7-11.com.tw/C2C/C2CWeb/MultiplePrintC2CPinCode.aspx`，
   **請以實際看到的為準**）

### 3.3 存成 PDF —— 不要碰列印對話框

**不要用 Ctrl+P、不要去操作系統的列印對話框。** Playwright 可以直接輸出：

```python
print_page.pdf(path=out, format="A4", print_background=True)
```

這會走跟「列印 → 另存為 PDF」完全一樣的 Chromium 列印管線，產出的檔案
和我現在手動存的一模一樣。

> `page.pdf()` 在 Chromium **headless 模式**才可用。如果用了
> `headless=False`（為了讓我能手動登入），請改用 CDP：
> ```python
> cdp = ctx.new_cdp_session(print_page)
> data = cdp.send("Page.printToPDF", {"printBackground": True})
> open(out, "wb").write(base64.b64decode(data["data"]))
> ```
> 這一段務必實測通過再往下做。

### 3.4 一次一筆，不要批次

**每次只勾選一筆訂單、印一次、存一個檔。** 跑 20 次迴圈對程式是零成本，
但可以完全避免「一張 A4 上有多張面單要裁切」的問題。

檔名直接用訂單號：`CM2609214719432.pdf`

> 如果實測發現賣貨便對「取交貨便代碼」有次數或頻率限制，才改成批次列印
> 再裁切 —— 那條路的技術細節見 **附錄 A**，我已經驗證過可行。

### 3.5 節流

每筆之間 **sleep 2～4 秒**。這是我自己的賣家帳號、做的也是我本來就會手動
做的事，但不要用機器的速度連續打人家的網站。

## 4. 階段 B：落地與驗證（**這一段最重要，不可以省**）

每一個 PDF 存檔後，**立刻打開它、讀出裡面的訂單號，確認跟檔名一致**。

```python
from pypdf import PdfReader
import re
text = PdfReader(path).pages[0].extract_text()
found = set(re.findall(r"CM\d{13}(?!\d)", text))
if found != {expected}:
    raise RuntimeError(f"{path} 內容是 {found}，與檔名不符，已中止")
```

**為什麼一定要做這一步**：面單上的物流條碼決定包裹屬於誰。檔名對不上
內容，會同時造成兩個問題 —— 那筆訂單的包裹貼著別人的面單（貨寄錯人），
而被冒名的那筆等於重複申報。

這不是假設。我手動另存時就發生過：`CM2609214719432.pdf` 裡面裝的其實是
`CM2609214719459` 的面單（兩個檔的物流條碼都是 `7M0001F868866901`）。
人工打檔名沒有任何東西會攔下來，所以這支程式必須自己攔。

**任何一筆驗證失敗 → 整批停止，不進入階段 C。**

### 4.1 資料夾規則

- 每一批建一個新資料夾：`C:\myship-bot\out\20260921-1418\`
- **絕對不要重用舊資料夾**。舊面單混進去傳上新比銳，倉庫會等一個早就
  寄出的包裹。
- 跑完把資料夾路徑印出來給我。

## 5. 階段 C：新比銳國際物流上傳

### 5.0 先探勘，不要盲寫（**這一步不能跳過**）

沒有人能憑空寫出操作這支程式的程式碼，因為控制項的名稱與階層只有在
我的電腦上才看得到。所以請**先交付一支探勘腳本**給我跑：

```python
# inspect_app.py — 把新比銳視窗的控制項樹印出來
import uiautomation as auto
win = auto.WindowControl(searchDepth=1, SubName="新比銳")   # 名稱請容錯
for c, depth in auto.WalkControl(win, maxDepth=8):
    print(" " * depth,
          c.ControlTypeName, "|", repr(c.Name), "|",
          repr(c.AutomationId), "|", repr(c.ClassName))
```

我會在以下三個畫面各跑一次，把輸出貼回給你：
1. 主畫面（還沒點任何東西）
2. 點進「蝦皮相關 → 蝦皮面單上傳」之後
3. 按「選取」跳出檔案對話框之後

**拿到這三份輸出之後，才開始寫階段 C 的程式碼。**

### 5.1 要做的動作

1. 啟動或切換到新比銳的視窗（沒開就啟動它，路徑寫在 `config.yaml`）
2. 點「蝦皮相關」
3. 點「蝦皮面單上傳」
4. 點「選取」
5. 檔案對話框出現後，**不要一個一個點清單**。直接在「檔案名稱」欄位
   輸入加引號的多檔字串，這是 Windows 標準對話框的多選寫法：
   ```
   "CM2609214719432.pdf" "CM2609214719459.pdf" "CM2609214719479.pdf"
   ```
   前面先把路徑切到本批資料夾（在檔名欄先輸入資料夾路徑按 Enter，
   或直接用完整路徑加引號）。
6. 按「開啟」
7. 按「識別」
8. **等待，並確認每一筆都出現「7-11」**。這是識別成功的唯一標誌。
   - 輪詢，最多等 60 秒
   - **只要有任何一筆沒有出現 7-11，就停下來、截圖、不要按上傳**
9. 全部都是 7-11 → 按「上傳」
10. 讀回上傳結果，印出來

### 5.2 這一段的硬性規則

- **`識別` 與 `上傳` 是兩個不同的動作，永遠不可以合併或跳過中間的檢查。**
- 找不到任何一個預期的按鈕 → 立刻停止 + 截圖，**不要去點座標**。
  用絕對座標點擊是這類程式最常見的災難來源：視窗一換位置就點到別的東西。
  一律用控制項名稱 / AutomationId 定位。
- 每一步都截圖存檔到 `out\<批次>\screenshots\`，出事才查得到。

## 6. 不可妥協的安全規則

1. **`--dry-run` 模式**：跑完階段 A + B，在階段 C 只做到「識別」，
   **不按上傳**，然後把結果印給我看。第一次上線一定用這個模式。
2. **只動清單上的訂單**。勾選前先讀那一列的文字，確認訂單號相符才勾。
   讀不到就跳過並記錄，不要「應該是這一列」。
3. **不要重試會造成副作用的動作**。網路逾時可以重試「讀取」，但
   「取交貨便代碼」「上傳」這類動作失敗就停下來報告，由我決定。
4. **全程記錄 log**：每一筆訂單、每一個動作、時間、結果，寫進
   `out\<批次>\run.log`。
5. **最後輸出一份對帳報告**：
   ```
   清單 3 筆
   ✅ 已印並驗證  3 筆  CM…432 CM…459 CM…479
   ❌ 失敗        0 筆
   ✅ 識別成功    3 筆（全部 7-11）
   ✅ 已上傳      3 筆
   ```
   有任何一筆對不上，報告要明確寫出是哪一筆、卡在哪一步。

## 附錄 A：如果改走「批次列印再裁切」

只有在賣貨便限制「取交貨便代碼」的頻率、逼得不能一筆一筆印時才需要。
以下是我實際拆過 2026/09/21 那份批次 PDF 得到的結論，可以直接用：

**版面**
- 頁面 A4：`594.96 × 841.92 pt`
- 一張 A4 排 **2 欄 × 2 列，共 4 張面單**
- 內容框：`x 29 → 567`，`y 28.06 → 812.92`（PDF 座標，原點左下）
- 裁切線：垂直 `x ≈ 274.36`；水平 `y ≈ 456.5`
- 格子間距：`246.11 × 357.16 pt`

**PDF 內部結構**（Chromium 印出來的，很規律）
- 傳統 xref、無物件流、無加密，內容是單一 FlateDecode 串流
- 開頭固定 `.24 0 0 -.24 0 841.92 cm`（y 軸翻轉）
- 每個 `BT…ET` 文字物件**剛好一個 `Tm`**，而且自帶 `Tf`
- 條碼是 `cm` + `/Xn Do`
- 同一個 `q…Q` 繪圖群組**會跨格子共用**，所以**不能照 q…Q 區塊拆**，
  必須逐一判斷每個文字物件與圖片落在哪一格

**怎麼決定格線 —— 這裡有個坑**

直覺做法是「把座標對間距取餘數，找最大的空白帶當裁切線」。
**在真實檔案上這是錯的**：面單裡「交貨便服務代碼」右邊有一塊 **76pt**
的留白，比面單之間的 **59pt** 間隙還寬。裁切線會切進面單裡，面單右緣的
一個字元被分到隔壁那張單 —— **表面上完全看不出來，但面單是錯的。**

正確做法是利用「每張面單版面完全相同」（本來就是同一個樣板）：

1. 以面單上的「寄貨訂單編號：CM…」當錨點，相鄰錨點距離即格子間距
2. 把每個元素座標換算成「距離各個錨點多遠」
3. 屬於面單的偏移量，在**每個**錨點底下都找得到對應元素（因為每張面單
   都有那個欄位）；頁首的列印時間、頁尾的網址只出現一次，對不上
4. 取交集 → 得到面單真正的佔用範圍
5. 裁切線切在「範圍外那段留白」的正中間

實測數值（相對於錨點的偏移）：`x −63.03 ~ +123.80`，`y −48.77 ~ +242.37`

**輸出**
保留整張 A4（頁首、頁尾、外框、裁切線都留著），只把其它格子的文字與
條碼拿掉。**不要裁成 10×14cm** —— 我現在單張列印上傳成功的檔案就是整張
A4，輸出跟已知可用的格式一致，風險最小。

**落在沒有任何面單的格子裡的東西（頁首列印時間、頁尾網址與頁碼）一律
保留**，每一份都要有，才跟單張列印的檔案長得一樣。

**產出後一定要再驗一次**（就是 §4 那段）：把自己做出來的 PDF 重新讀一遍，
確認裡面只剩一個訂單號而且正是預期的那個，不符就整批中止。

> 這套邏輯我已經用 TypeScript 實作並驗證過（健康優選後台的「面單處理」
> 功能，原始碼在 `lib/myship/labelPdf.ts`）。Python 有現成的 PDF 函式庫，
> 會比我那版好寫很多，但**上面那個 76pt 的坑跟語言無關，一定會踩到**。
